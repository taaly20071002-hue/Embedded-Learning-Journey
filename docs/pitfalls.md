> 每个坑都是**实际踩过并搞明白**的。
> 这份文档的价值在于:**这些错误编译器大多不会报,只能靠经验和逻辑排查。**

## 一、GPIO 与按键

### 坑 1:按键完全没反应,但代码看起来没问题

**现象**:数码管/LCD 数值不变,按键无响应。

**原因一:引脚定义错了**(最常见!)

```c
/* ❌ 照抄教程的引脚 */
if(P3_2 == 0) KeyNumber = 1;    /* 但我的板子是 P3.1! */
if(P3_3 == 0) KeyNumber = 2;
if(P3_4 == 0) KeyNumber = 3;
if(P3_5 == 0) KeyNumber = 4;

/* ✅ 实测后的正确引脚 */
if(P3_1 == 0) KeyNumber = 1;    /* K1 */
if(P3_0 == 0) KeyNumber = 2;    /* K2 */
if(P3_2 == 0) KeyNumber = 3;    /* K3 */
if(P3_3 == 0) KeyNumber = 4;    /* K4 */
```

**怎么测**:读整个 P3 端口,按键后看哪个位变 0(详见 [pinout.md](pinout.md))。

**原因二:代码写在了 `while(1)` 外面**

```c
/* ❌ 按键处理永远执行不到 */
void main() {
    while(1) {
        KeyNum = Key();
        ...
    }                    /* ← while 在这里结束 */
    
    if(KeyNum) {         /* ★ 死代码! */
        if(KeyNum == 1) THigh++;
    }
}
```

**教训**:**`while(1)` 是死循环,写在它外面的代码一次都不会执行。** 编译器不会报错。

---

### 坑 2:按一下键触发好几次

**现象**:按一次 K1,数值加了好几个。

**原因**:按键机械抖动(按下/松开瞬间会抖动 5~10ms)。

**解决**:消抖

```c
/* 方法一:延时消抖(简单)*/
if(P3_1 == 0) {
    Delay(10);              /* 等抖动过去 */
    if(P3_1 == 0) {         /* 再确认一次 */
        KeyNumber = 1;
        while(P3_1 == 0);   /* 等松开 */
    }
}

/* 方法二:状态机消抖(推荐,不阻塞)*/
if(NowKey != 0 && LastKey == 0) {   /* 只在"按下瞬间"触发 */
    LastKey = NowKey;
    return NowKey;
}
```

## 二、显示(LCD1602 / 数码管)

### 坑 3:LCD1602 显示乱码 / 只显示部分字符

**原因:RW 引脚定义错了**

```c
/* ❌ 教程默认(江协科技用的 P2.5)*/
sbit LCD_RW = P2^5;

/* ✅ 我的板子实测是 P3.7 */
sbit LCD_RW = P3^7;
```

**原理**:
```
RW = 0 → 写模式(LCD 接收数据)✅
RW = 1 → 读模式(LCD 不接收)❌

如果代码控制的 P2.5 是悬空脚,而 LCD 真正的 RW(P3.7)一直是高电平
→ LCD 永远处于"读模式" → 写什么都进不去 → 显示乱码
```

**教训**:**引脚定义必须对照自己板子的原理图。**

---

### 坑 4:`LCD_ShowChar` 显示乱码

```c
LCD_ShowChar(2, 1, "-");   /* ❌ 双引号 = 字符串(指针)*/
LCD_ShowChar(2, 1, '-');   /* ✅ 单引号 = 单个字符 */
```

**原因**:

| 写法 | 类型 | 内存 | 传给 char 参数 |
|---|---|---|---|
| `'-'` | `char` | 1 字节:`0x2D` | ✅ 正确 |
| `"-"` | `char*` | 2 字节:地址 | ❌ 取地址低字节 → 乱码 |

**编译器警告**:`WARNING C214: 'Argument': conversion: pointer to non-pointer`

**教训**:**单引号是字符,双引号是字符串。**

---

### 坑 5:数码管有残影(重影)

**原因**:动态扫描时,上一位的段码还没清除,下一位就点亮了。

**解决**:消影

```c
Nixie(1, bai);
P0 = 0x00;         /* ★ 消影:清空段码 */
Nixie(2, shi);
P0 = 0x00;
Nixie(3, ge);
P0 = 0x00;
```

## 三、定时器与中断

### 坑 6:定时器时间不对(差了 60 多倍)

**原因:模式 1 不会自动重装初值!**

```c
/* ❌ 只在初始化时装一次 */
void Timer0_Init() {
    TMOD = 0x01;       /* 模式 1:16 位 */
    TH0 = 0xFC;        /* 初值 */
    TL0 = 0x18;
    ET0 = 1;
    EA  = 1;
    TR0 = 1;
}

/* 第一次 1ms ✅,第二次变 65.5ms ❌ */

/* ✅ 必须在中断里重装 */
void Timer0_Routine() interrupt 1 {
    TL0 = 0x18;        /* ★ 重装 */
    TH0 = 0xFC;
    ...
}
```

**原理**:

| 模式 | 溢出后行为 |
|---|---|
| 模式 0(13 位) | 从 0 开始 |
| **模式 1(16 位)** | **从 0 开始 → 必须手动重装** |
| 模式 2(8 位自动) | 自动从 TH0 装入 TL0 |

---

### 坑 7:中断里做太多事导致响应变慢

**原因**:中断服务函数里调用 `Delay()` 或 `LCD_ShowNum()` 这类耗时操作。

**解决**:**中断里只设标志位,主循环里处理**

```c
/* ✅ 正确的分工 */
volatile unsigned char flag = 0;

void Timer0_Routine() interrupt 1 {
    TL0 = 0x18;
    TH0 = 0xFC;
    flag = 1;              /* 只设标志 */
}

void main() {
    while(1) {
        if(flag) {
            flag = 0;
            LCD_ShowNum(...);   /* 耗时操作放主循环 */
        }
    }
}
```

**变量要加 `volatile`** —— 否则编译器可能优化掉"看起来没变"的变量。

## 四、通信协议

### 坑 8:I2C 读不出数据(AT24C02)

**原因 1:函数少了 `return`**

```c
/* ❌ 忘了返回 */
unsigned char AT24C02_ReadByte(unsigned char WordAddress)
{
    unsigned char Data;
    /* ... 读取过程 ... */
    /* 少了 return Data; ← 返回值是随机的! */
}

/* ✅ */
    return Data;
```

**原因 2:应答位处理错误**

```c
/* ❌ 用 = 而不是 |= */
if(i < 8 || Mask != 0) { Ack = 0; }   /* 覆盖了之前的应答! */

/* ✅ */
if(i < 8 || Mask != 0) { Ack |= 0; }  /* 保持应答位 */
```

**原因 3:ACK 后没释放 SCL**

```c
/* ❌ 忘了拉低 SCL,导致 SDA 被卡住 */
if(Ack == 0) {
    I2C_SDA = 1;
    return 0;
}

/* ✅ */
if(Ack == 0) {
    I2C_SDA = 1;
    I2C_SCL = 0;    /* ★ 释放时钟线 */
    return 0;
}
```

**教训**:**I2C 的每个时钟周期结束后,SCL 都要回到低电平(空闲态)。**

### 坑 9:单总线(DS18B20)读到全是 0xFF

**原因 1:for 循环漏了 `i++`**

```c
/* ❌ 死循环 */
for(i = 0; i < 8; i)
{
    if(OneWire_ReceiveBit()) Byte |= (0x01 << i);
}

/* ✅ */
for(i = 0; i < 8; i++)
```

**原因 2:发送位后没释放总线**

```c
/* ❌ 结束时总线还是低电平 */
void OneWire_SendBit(unsigned char Bit) {
    OneWire_DQ = 0;
    ...
    OneWire_DQ = 0;      /* 错! */
}

/* ✅ */
    OneWire_DQ = 1;      /* 释放总线(空闲高电平)*/
```

**原理**:单总线协议要求**两次通信之间总线保持高电平(空闲态)**。如果保持低电平,从设备会误认为是复位脉冲。

**原因 3:用了 void 函数当条件**

```c
if(OneWire_SendByte()) { }   /* ❌ 错误 C218:void-type in controlling expression */

if(OneWire_ReceiveBit()) { } /* ✅ 这里应该接收一位 */
```

### 坑 10:DS18B20 读到 85℃(恒定值)

**原因:没等温度转换完成**

```c
/* ❌ 启动转换后立刻读 */
DS18B20_ConvertT();
T = DS18B20_ReadT();      /* 读到 85℃ 或旧值 */

/* ✅ */
DS18B20_ConvertT();
Delay(750);               /* 12 位精度最长 750ms */
T = DS18B20_ReadT();
```

**85℃ 是什么**:DS18B20 上电默认值(`0x0550`),表示"还没做过转换"。

**转换时间表**:

| 精度 | 转换时间 |
|---|---|
| 9 位 | 93.75 ms |
| 10 位 | 187.5 ms |
| 11 位 | 375 ms |
| **12 位(默认)** | **750 ms** |

**教训**:**所有"启动转换"类操作都要等完成** —— ADC、EEPROM 写入、Flash、传感器。

### 坑 11:DS1302 时钟不走 / 读出来是 89 秒

**原因 1:秒寄存器的 CH 位没清零**

```c
/* ❌ 直接写秒值,CH 位可能还是 1(时钟停振)*/
DS1302_WriteByte(0x80, 0x30);

/* ✅ 保证 CH = 0 */
Sec = 0x30;                    /* BCD 码 */
DS1302_WriteByte(0x80, Sec);   /* CH 位(bit7)= 0 → 时钟启动 */
```

**原因 2:BCD 码没转换**

```c
/* ❌ 把 BCD 码当十进制显示 */
Second = DS1302_ReadByte(0x81);    /* 读到 0x23(BCD,表示 23 秒)*/
LCD_ShowNum(1, 1, Second, 2);       /* 显示 35!错! */

/* ✅ 先转换 */
second = (BCD >> 4) * 10 + (BCD & 0x0F);   /* 0x23 → 23 */
LCD_ShowNum(1, 1, second, 2);               /* 显示 23 ✅ */
```

**原因 3:SCLK 结束时没拉低**

```c
/* ❌ 每个字节结束后 SCLK 是高电平 */
for(i = 0; i < 8; i++) {
    DS1302_IO = ...;
    DS1302_SCLK = 1;
    /* 少了 SCK = 0 */
}

/* ✅ */
    DS1302_SCLK = 1;
    DS1302_SCLK = 0;    /* 每个位结束时拉低 */
```

## 五、工具与工程

### 坑 12:Keil 打不开工程 / 工程树空白

**现象**:Keil 报错,或者打开后左侧没有文件列表。

**原因**:`project.uvproj` 变成 **0 字节**(Keil 崩溃 / 云同步冲突 / 磁盘满)。

**解决**:

```
① 检查文件大小:ls -la project.uvproj(0 字节 = 坏了)
② 从其他工程的 uvproj 复制一份
③ 修改里面的 <Files> 列表,加上本工程的 .c 文件
④ 重新打开 Keil
```

**教训**:**重要工程要么备份,要么上 Git** —— 这就是为什么要用版本管理。

---

### 坑 13:编译器不报错,但程序行为不对

**这类 bug 最危险**,因为编译通过、下载成功,就是不工作。

**典型场景**:

| 类型 | 例子 | 表现 |
|---|---|---|
| 死循环 | `for(i=0;i<8;i)` 漏 i++ | 程序卡死 |
| 死代码 | 代码写在 `while(1)` 外面 | 永远不执行 |
| 逻辑错 | `if(a = 0)` 用了赋值 | 条件永远假 |
| 未初始化 | 局部变量没用先读 | 随机值 |
| 数组越界 | `arr[10]` 但数组长度 10 | 覆盖相邻内存 |

**排查方法**:

```
① 加"可见信号":在关键位置翻转 LED / 显示数字,看执行到哪
② 二分法:注释掉一半代码,看问题出在哪半边
③ 单独测试:把疑似有问题的函数单独拿出来跑
④ 对照手册:逐行核对时序图
```

## 六、调试方法论

### 硬件问题的排查顺序

```
① 供电     → 板子上电源灯亮吗?万用表测 5V/3.3V
② 接线     → 线插紧了吗?杜邦线断了吗?
③ 引脚     → 代码里的引脚 = 板子上的引脚吗?(端口探测法)
④ 器件     → 换个器件试试(是不是器件坏了)
⑤ 上拉     → I2C/单总线需要上拉电阻吗?
```

### 软件问题的排查顺序

```
① 编译警告 → 全部看一遍(警告往往就是 bug)
② 死循环   → 检查所有 for/while 的循环条件
③ 初始化   → 外设初始化顺序对吗?寄存器配置对吗?
④ 时序     → 对照数据手册的时序图逐条核对
⑤ 等待     → 有没有漏掉"等转换完成"?
```

### 一句话总结

> **硬件问题先查"通不通",软件问题先查"跑没跑到"。**

## 附录:常见错误码速查

| 错误码 | 含义 | 常见原因 |
|---|---|---|
| `C141` | 语法错误 | 少分号、括号不匹配 |
| `C202` | 未定义的标识符 | 变量没声明、头文件没包含 |
| `C214` | 指针转非指针 | 字符串传给 char 参数 |
| `C218` | void 类型在控制表达式 | void 函数放在 if/while 里 |
| `C280` | 变量未使用 | 声明了没用(警告,无害) |
| `L104` | 无法打开文件 | 路径错、文件不存在 |
| `L107` | 地址空间溢出 | 代码太大(换更大芯片或优化) |
