# Embedded-Learning-Journey

> **51 单片机学习代码仓库** —— 记录从零开始学嵌入式开发的每一步。
>
> 从点亮第一个 LED,到驱动 DS18B20 温度传感器,27 个完整工程、84 个源文件。

---

## 简介

这个仓库记录了一名软件工程专业学生,在大学第一学期从零学习 51 单片机的完整过程。

**不是教程的复制粘贴**,而是:
- 每个实验都自己敲过一遍
- 每个 bug 都自己定位过一遍
- 每次踩坑都记录在案(见 [踩坑记录](#踩坑记录真实经历))

如果你也在学 51 单片机,这里的代码和踩坑记录或许能帮你少走些弯路。

## 关键引脚表(实测确认)

> ⚠️ 不同开发板引脚不同,**这份表是实测出来的,不是抄教程的**。
> 测法:读整个端口(P3),按键后看哪一位变 0 → 反推引脚。

| 外设 | 引脚 | 备注 |
|---|---|---|
| LED | `P2.0` ~ `P2.7` | **低电平点亮** |
| 独立按键 K1 | `P3.1` | 低电平按下 |
| 独立按键 K2 | `P3.0` | 低电平按下 |
| 独立按键 K3 | `P3.2` | 低电平按下 |
| 独立按键 K4 | `P3.3` | 低电平按下 |
| 矩阵键盘 | `P1.0` ~ `P1.7` | 4×4,行 P1.4~P1.7,列 P1.0~P1.3 |
| 蜂鸣器 | `P1.5` | |
| 数码管段码 | `P0` | 共阴极段码 |
| 数码管位选 | `P2.2` / `P2.3` / `P2.4` | 经 74HC138 译码 |
| LCD1602 | RS=`P2.6`, RW=`P3.7`, EN=`P2.7`, D0~D7=`P0` | **RW 是 P3.7,不是 P2.5!** |
| 串口 | RXD=`P3.0`, TXD=`P3.1` | 与 K1/K2 复用 |
| I2C(AT24C02) | SCL=`P2.1`, SDA=`P2.0` | |
| DS1302 | SCLK=`P3.6`, IO=`P3.4`, CE=`P3.5` | |
| 74HC595 | SER=`P3.4`, SCK=`P3.6`, RCK=`P3.5` | |
| DS18B20 | DQ=`P3.7` | 单总线,需 4.7k 上拉 |

## 踩坑记录(真实经历)

> 这一节是**这个仓库最有价值的部分** —— 每个坑都是我实际踩过、并且搞明白了的。
> 面试时被问"你遇到过什么问题",这些就是最好的答案。

### 1. LCD1602 只显示乱码 → RW 引脚定义错了

```c
/* ❌ 教程里的默认值(江协科技用的是 P2.5)*/
sbit LCD_RW = P2^5;

/* ✅ 我的板子实测是 P3.7 */
sbit LCD_RW = P3^7;
```

**现象**:LCD 显示乱码,或者只显示部分字符。
**原因**:RW 引脚没接对 → 控制的 P2.5 是悬空脚,而 LCD 真正的 RW(P3.7)一直是高电平 = **读模式**,写什么都进不去。
**教训**:**引脚定义必须对照自己板子的原理图,不能照抄教程。**

### 2. 单总线读数据全是 0xFF → for 循环漏了 i++

```c
/* ❌ 死循环!i 永远不会变 */
for(i = 0; i < 8; i)
{
    ...;
}

/* ✅ */
for(i = 0; i < 8; i++)
{
    ...;
}
```

**现象**:程序卡死,或者读到的数据全错。
**原因**:`for` 的第三个表达式漏了 `i++` → 条件永远成立 → **死循环**。
**教训**:**这种错误编译器完全不报错**(语法合法),最难查。写循环后要检查三个部分都在。**

### 3. DS18B20 读到 85℃ → 没等温度转换完成

```c
/* ❌ 启动转换后立刻读 */
DS18B20_ConvertT();
T = DS18B20_ReadT();      /* 读到 85℃(上电默认值)*/

/* ✅ 等待 750ms(12 位精度最长转换时间)*/
DS18B20_ConvertT();
Delay(750);
T = DS18B20_ReadT();
```

**教训**:**所有"启动转换"类操作都要等完成**(ADC 转换、EEPROM 写入、Flash 烧写、DS18B20 测温)。

### 4. 按键完全没反应 → 代码写在了 while(1) 外面

```c
/* ❌ */
void main() {
    while(1) {
        KeyNum = Key();
        ...
    }               /* while 结束 */
    
    if(KeyNum) {    /* 永远执行不到! */
        if(KeyNum == 1) THigh++;
    }
}

/* ✅ 所有逻辑都在循环里 */
void main() {
    while(1) {
        KeyNum = Key();
        if(KeyNum) { THigh++; }
        ...
    }
}
```

**教训**:**`while(1)` 是死循环,写在它外面的代码永远不执行。** 编译不报错,只能靠逻辑检查。

### 5. `LCD_ShowChar` 传了字符串 → 显示乱码

```c
LCD_ShowChar(2, 1, "-");   /* ❌ 双引号 = 字符串(指针),警告 C214 */
LCD_ShowChar(2, 1, '-');   /* ✅ 单引号 = 单个字符 */
```

**教训**:**单引号是字符,双引号是字符串。** 传给 `char` 参数的必须是单引号。

### 6. AT24C02 读不出数据 → 函数少了 return

```c
/* ❌ 忘了返回读到的值 */
unsigned char AT24C02_ReadByte(unsigned char WordAddress)
{
    unsigned char Data;
    ...
    Data = ...;
    /* 少了 return Data; */
}

/* ✅ */
    return Data;
```

**教训**:**"函数不返回值"这类 bug,编译器可能只报警告甚至不报**(如果调用处不检查返回值)。写完驱动要逐个函数检查 return。

### 7. Keil 打不开工程 → project.uvproj 变成 0 字节

**现象**:Keil 报错,或者工程树空白。
**原因**:Keil 异常关闭 / 云同步冲突,导致工程文件被截断成 0 字节。
**解决**:从其他工程的 `uvproj` 复制一份,改里面的文件列表。
**教训**:**重要工程要备份(或直接上 GitHub)** —— 这就是为什么要用 Git。

### 8. 按键引脚全是错的 → 用"端口探测法"实测

**现象**:按键完全无反应(代码逻辑没问题)。
**原因**:照抄教程的 `P3.2/P3.3/P3.4/P3.5`,但我的板子是 `P3.1/P3.0/P3.2/P3.3`。
**解决**:**写个程序读整个 P3 端口显示到数码管**,按键后看数字变化:

| 显示值 | 十六进制 | 哪个位变 0 | 引脚 |
|---|---|---|---|
| 255 | FF | 无 | 没按 |
| **253** | FD | bit1 | **P3.1** |
| **254** | FE | bit0 | **P3.0** |
| **251** | FB | bit2 | **P3.2** |
| **247** | F7 | bit3 | **P3.3** |

**教训**:**不确定引脚时,"读整个端口 + 观察变化"比翻手册快得多。** 这是嵌入式调试的基本功。

## 快速上手

### 编译

```
① 用 Keil C51 打开某个工程的 project.uvproj
② Project → Rebuild all target files(F7)
③ 生成 Objects/project.hex
```

### 烧录

```
① 打开 STC-ISP
② 选择芯片型号:STC89C52RC
③ 选择串口(COMx)
④ 打开 hex 文件
⑤ 点击"下载/编程"
⑥ 给开发板断电再上电(冷启动)
```

### 调试技巧

| 场景 | 方法 |
|---|---|
| LCD 不显示 | 先测引脚(示波器/端口探测) |
| 程序卡死 | 加 LED 翻转,看跑到哪一步 |
| 通信失败 | 检查位操作时序、等待时间 |
| 读数全是 0xFF/0x00 | 器件没响应 → 查接线/引脚/上拉 |
